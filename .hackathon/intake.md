## 2. Eligibility — CONFIRMED
- Open to college students, graduates and working professionals, **age 16–25**.
- Both **Technical** and **Non-Technical** participant categories (separate rubrics + separate prizes).
- **Team of 2–4 members required** to compete. Individuals may attend only as visitors.
- Cross-college / cross-organization teams allowed.
- Registration fee applies and is **non-refundable**. No travel/accommodation/food reimbursement.
  No accommodation provided. Not an overnight-at-venue event (you may work at your own lodging at night).

Notable detail captured:
- **PS01** wants personalized career roadmaps linking student profiles/academic records, courses &
  certifications, internships & jobs, AI resume improvement, and government employment opportunities.
- **PS02** wants a unified campus platform (student lifecycle, admin services) plus AI features such as
  predictive student performance and personalized learning recommendations.
- **PS05** wants an AI solution for a real public service (grievance redressal named explicitly), using
  AI/predictive analytics, improving delivery time and citizen experience.
- **PS06** is the most fully specified. Framed as **"Prevention → Detection → Response → Recovery → Trust"**
  across the assessment lifecycle. Sub-asks include: real-time monitoring of exam infrastructure and
  candidate sessions; early prediction of technical/operational failure; automated incident detection,
  classification and escalation; backup and disaster recovery for exam continuity; tamper-evident storage
  of exam and response data; detection of suspicious/abnormal exam patterns; automated reconciliation and
  validation of candidate responses; candidate communication and live status during disruptions;
  decision support on whether to reschedule/re-conduct; fairness when an exam is disrupted; post-exam audit
  trail and evidence-based reporting; AI analytics on systemic risk. Stated goal: avoid unnecessary
  re-conduct of exams.

## 4. Judging criteria — CONFIRMED, with weights

### Technical track (total 100%)
| Weight | Criterion |
|---|---|
| 20% | Innovation & Originality |
| 20% | Prototype / MVP (functionality, completeness, usability) |
| 15% | Problem Understanding |
| 15% | Technical Feasibility (architecture, implementation approach) |
| 15% | Impact on Higher Education / Governance |
| 10% | Scalability & Sustainability |
| 5%  | Presentation & Demo |

### Non-Technical track (total 100%)
| Weight | Criterion |
|---|---|
| 20% | Technical Implementation |
| 15% | Innovation & Creativity |
| 15% | Solution Quality |
| 10% | Problem Understanding |
| 10% | UI/UX Design |
| 10% | Feasibility & Scalability |
| 10% | Impact / Value |
| 10% | Presentation & Demo |

Strategic read: on the technical track **40% is Innovation + working Prototype**, and only 5% is the
pitch. Demo theater alone loses. A narrow, genuinely working golden path plus a crisp originality claim
is the winning shape. 15% "Impact on Higher Education / Governance" means the MP-specific framing must
be explicit, not implied.

## 5. Submission kit — CONFIRMED (portal: /project-submission, draft + hard "lock")
Ten items; **max file size 1 MB each** (this is a real constraint — compress PDFs).
1. Solution Synopsis / Executive Summary — mandatory (file)
2. Solution Presentation, PDF — mandatory (file)
3. Problem Statement & Proposed Solution — mandatory (file)
4. Innovation & Differentiation Note — mandatory (file)
5. Impact & Benefits Document — mandatory (file)
6. Implementation / Feasibility Plan — mandatory (file)
7. Technology Architecture / Technical Approach — conditional, **required for Technical track** (file)
8. Prototype / Demo / Proof of Concept — mandatory (file)
9. **Code Repository URL** — conditional, required for Technical track (URL field; placeholder in code is
   `https://github.com/org/repo`)
10. "Why Should This Solution Be Selected?" — mandatory (free-text area)

FAQ also states the end deliverable is: working prototype/demo, source-code repo link, short description
of problem/solution/tech stack, and a **5–10 minute pitch deck of up to 10 slides**.

## 9. CONFLICT FOUND — flag for the human
The FAQ says projects **must be created during the hackathon** and pre-built projects are ineligible.
The published agenda, however, says the 10:30 session gives "mentor suggestions on **premade
presentations/solutions** followed by revamping if required," and the submission kit is document-heavy
(6 of 10 mandatory items are write-ups, not code). These point in opposite directions.

Practical reading, to be confirmed with the organizers by email before 09 Oct:
- Research, problem framing, user interviews, deck skeletons and architecture/design thinking done in
  advance appear to be expected.
- Shipping a repo with pre-written application code is a disqualification risk.
This single question determines whether the BUILD phase happens now or on 09 October.
